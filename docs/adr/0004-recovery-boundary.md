# ADR-0004：邮箱仅重置密码，保留强因素恢复边界

- 状态：接受。
- 日期：2026-10-07。
- 关联：T02.03/T02.07、T07/T08/T09/T14/T18。
- 验收：T07-PWD-01/02/03/04、T08-MFA-03/04、T09-PK-02/04、T14-ADM-02/03、T18-ACC-02；E07/E08/E09/E10/E27。

## 背景与决定

平台有邮箱密码、TOTP、Passkey和一次恢复码。邮箱被控制不应直接取消MFA或添加攻击者Passkey。密码找回统一202，15分钟reset action仅在明确POST确认时单次消费；同事务更新密码摘要/credential_version、撤销全session/grant并创建通知outbox。保留TOTP/Passkey，不自动登录，不自动启用disabled用户。

尚无MFA的普通账号可用最近5分钟密码重新认证首次绑定因素及改密码。已有MFA账号新增/删除因素、改密码或重建恢复码必须最近5分钟TOTP、Passkey UV或单次恢复码；仅密码不够。Passkey登录由库验证UV=true，可满足强认证，不能虚假声明硬件保护；恢复码128位以上随机、十个、仅显示一次，原子消费，重建全部旧码失效。

TOTP种子至少160位、AEAD绑定user/purpose、30秒步/六位/前后一步，last_step原子拒绝已用或更早步。challenge最多五次、五分钟；恢复码与挑战及登录/reauth结果在同事务消费，不能仅提交码就更新任意session。管理员始终强认证；首个未绑因素管理员仅受限绑定权限，后续成员只能授予已verified且有因素的已有用户。

禁止管理员/客服无条件清MFA、代登录、开放邀请链接或邮箱重置后创建新Passkey。不删除最后有效登录方式；当前所有注册账号仍有密码，不扩展Passkey-only。全部凭证丢失后的人工身份核验与恢复政策不在第一版，不能用临时后门完成验收。

## 规范与产品规则的区别

WebAuthn Level3 §7.1/§7.2要求challenge/origin/RP哈希/签名和根据策略验证UV；本系统产品策略强制UV。规范§6.1.1与§7.2说明signCount异常是克隆信号而非证明，可能包含竞争；同步Passkey必须按库/规范处理，不能一概要求计数递增。上述邮箱/MFA恢复政策、5分钟窗口、码数量与期限是已选产品契约，不声称由WebAuthn标准强制。

## 影响与验证

真实用户需要事先保存恢复码或保有另一因素；界面在成功绑定/重建后清楚提示并只展示一次。安全动作提交后发送通知；SMTP故障由outbox重试，不撤回安全动作。T07/T08/T09执行邮箱恢复保留MFA、码并发消费、错误origin/UV及真实设备取消回退，T14保护管理员初始化及最后成员。当前ADR不表示这些功能已实现；来源见 [spec-sources.md](../evidence/T02/spec-sources.md)。
