# T14 契约与实现校正

管理审计API采用已有AuditEvent正式字典，不重命名已写入事件。原OpenAPI审计枚举使用规划期别名（如session.revoked/oauth.refresh.reuse_detected），与已实现安全审计字典不同，现同步真实as_str枚举及示例；不能把别名转换当作实际审计事件。

首个无因素管理员保留/me、登录退出、预认证/CSRF和本人首次因素绑定必要流程；其他后台及授权路径拒绝。无因素只绑定，已配置因素进入后台仍要求最近五分钟强认证，普通用户后台403。该限制是T14.03明确“只有绑定权限”的实现边界，所有handler后端独立校验，不依赖前端隐藏。

最后可用管理员保护覆盖自行删除最后TOTP/Passkey，与管理删除/禁用使用同一全局保护锁，锁在user行之前；有其他自身因素或另一个可用管理员才允许删除。409使用ADMIN_LAST_MEMBER，原AUTH_LAST_LOGIN_METHOD保留其独立登录方式语义。只删除成员/停用户而放任删因素会绕过可管理性，因此这项属于T14.04同一必要保护。
