# 分段容量测试的令牌快照修复

共享Redis连接后的 [第二次短阶梯报告](load-capacity-2026-10-08T17-04-23-472Z-failure.json) 整体退出1，原始结果保留。1倍与2倍档目标计数、延迟与身份验证通过，真实刷新和Redis连接/调用均无失败；4倍有8次无效身份，8倍有大量无效身份及密码队列超时。

代码复核确认阶梯后面的新VU在360秒才开始工作，初次却使用setup时获取的原令牌并把本地更新时间设为当前时间。其原访问令牌可能已超过五分钟有效期。控制池已经真实更新，脚本仍用旧快照，因此后档无效身份不能全部归为后端性能问题。

容量脚本现为新VU首次请求时读取当前控制池，每分钟更新；正式单项/综合900秒脚本保持原逻辑和门槛。新增有意义的时钟测试证明晚启动的VU使用当前令牌、59.999秒不刷新且60秒刷新，逻辑测试与ESLint退出0；修复后短阶梯另存新报告，不删除这次失败。

8倍档密码计算出现实际250ms队列截止，且同机负载器存在调度丢弃，这些独立限制仍需保留；没有提高并发、降低Argon2成本、放宽超时或修改流量门槛。修复仅防止过期的压测凭证混入容量结论。
