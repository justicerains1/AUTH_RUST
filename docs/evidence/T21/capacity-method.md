# T21 本机容量阶梯测量方法

这是独立于正式十五分钟场次的短时实验，用于定位限制，不替代参考硬件验收。测试只接受明确APP_ENV=test、loopback及identity_test，复用十万账号/二十客户端/十万授权、2048会话与真实512个OAuth家族；参数仍Argon2id64MiB/t3/p1、四并发、250ms等待，限流与权威验证保持。

`npm run test:capacity`依次以混合300+50+5 RPS的1、2、4、8倍测量，每档60秒预热、60秒采样，总480秒；下一档开始时间固定。所有请求使用真实客户端Basic、会话Cookie及密码/CSRF流程，过期令牌池由真实refresh更新。任何503、429、无效身份、调度丢弃或计数/延迟门槛失败都返回非零并保存失败。每档准确速率用其目标60秒计数判断，不能把k6按整个480秒计算的子指标rate当该档RPS。

每15秒保存同一API的真实SQL完成/获取连接等待/密码排队与并发、PG等待事件和容器资源。客户端与控制池也消耗同机资源，所以超载不能推定指定参考机器或生产最大容量。后档若令牌池更新失败，既有凭证可能到期，必须将后档标记“令牌池失效影响”；不能把此时invalid token错误解释为单一后端性能限制。

首次场次 [完整失败报告](load-capacity-2026-10-08T15-48-43-290Z-failure.json) 保留：1倍档目标请求全部完成、无错误、p95状态5ms/账号1ms/密码138ms；2倍档出现503，后续真实refresh失败，后档不作为独立有效容量结论。具体等待/查询与连接行为另由 [容量分析](capacity-first-analysis.md) 复核。不改阈值掩盖失败，也不通过缩短正式900秒测量放行。
